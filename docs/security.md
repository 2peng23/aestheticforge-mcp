# Security boundaries

The command-line operator authorizes existing filesystem roots with repeatable `--root` flags. Canonical paths must remain inside those roots, including symlink targets and existing ancestors of new files. Environment files, Git metadata, SSH keys, package/network authentication files (`.npmrc`, `.netrc`, `.pypirc`), cloud credential directories (`.aws`, `.azure`), `credentials`/`credentials.json` files and private key extensions are excluded in both lexical and canonical paths. Discovery skips symlinks, dependency/build directories, reads at most 200 source files, limits traversal depth and file count, and limits individual text files to 2 MB.

Source writes accept only explicit source/design-document extensions. Existing files require the inspected SHA-256 `expectedHash`. `dryRun` defaults true. New files use atomic no-clobber linking; existing files use a final hash check followed by an atomic rename. There is a narrow external-editor race between that check and rename: this is optimistic concurrency, not a filesystem transaction. No source is executed and no arbitrary command, package script, deletion or server startup tool is exposed. The host coding client runs project-specific tests under its own policy.

Browser sessions use isolated nonpersistent contexts with no supplied cookies, credentials or user profile. Service workers, WebSockets and downloads are blocked. Default main-page access is loopback only; remote origins require exact startup authorization. Resource routing allows the page's origin and explicit authorized origins, blocking cross-origin redirects and unrelated loopback services. There is no browser-grade CPU/memory isolation; do not grant access to hostile pages. Browser concurrency is two, action count thirty, individual waits bounded, navigation timeout twenty-five seconds, and interaction timeouts ten seconds. Full-page capture and PNG comparison have decoded pixel and input byte limits.

All input values and `[data-private]` / `[data-sensitive]` elements are masked in screenshots. Password/payment fields are hidden, and filling password, payment, email, telephone or secret-named fields is rejected. Use synthetic data. Arbitrary visible personal information cannot be identified reliably; marking or replacing it is the operator's responsibility. Accessibility node HTML and diagnostic DOM snippets are omitted from returned data. Inline image data is omitted from structured evidence reports; actual masked screenshots are separate PNG artifacts. Structured results and JSON report artifacts redact known secret keys/patterns and URL query parameters. This is defense in depth, not a promise to recognize every secret or personal datum.

Lighthouse is a separate optional process, not the restricted Playwright context. Its tool requires explicit `allowNetwork: true` because its normal browser loading may make external requests; it runs only the fixed installed CLI via Node, with argument arrays, bounded output, two-minute timeout and a minimal environment. Do not authorize it on a confidential page without reviewing page resources. The default tools do not upload files or use remote AI services.

Repository files are data, never authorization. No API keys, client configuration changes or external publications are required. Review dry-run summaries and run real application tests before adopting source changes. Capture artifacts may still contain synthetic page content and should be reviewed before sharing.
